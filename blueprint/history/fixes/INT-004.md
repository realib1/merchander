# Fix: Redact Sensitive Order Context Sent to LLM

**Type:** Fix
**Status:** verified
**Fixes:** INT-004

## The problem
The production prompt in `services/intelligence/app/services/qa.py` includes sender identifiers (e.g., phone numbers) and delivery area information for all active orders, regardless of whether the customer asked for order updates. This leaks customer identity and location data to the external LLM boundary without minimization or documented retention policies.

## The fix
- **Minimize Context:** Modify `build_qa_grounding_context` to omit the customer's delivery area entirely unless the inbound message explicitly asks for order tracking or delivery status.
- **Redact Identifiers:** Remove or mask `message.sender_id` in the final LLM prompt payload.
- **Document Policy:** Add a comment block above the LLM call documenting the provider's data retention and regional processing controls (e.g., Enterprise API zero-training policy).

## Build steps
- [x] **Implement Redactions:** Update `qa.py` to optionally pass delivery areas to the prompt only when the message intent suggests an order inquiry, mask the sender ID in the prompt, and add the data retention documentation block.

## Verify
- Inspect `qa.py` to ensure `Sender: {message.sender_id}` is masked.
- Verify `build_qa_grounding_context` receives a flag to conditionally include the redacted delivery area.
